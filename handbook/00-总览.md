## 一、先搞清楚：你学的到底是什么

### 1. 运维在干什么

一句话：**保证线上系统活着、不慢、不出事；出了事能最快找到原因。**

具体是四件事：

| 事 | 例子 |
|---|---|
| 部署 | 把程序放到服务器上跑起来 |
| 监控 | 盯着它，知道它现在健康不健康 |
| 排障 | 出问题时，从一堆数字和日志里找到真正的原因 |
| 自动化 | 把重复操作写成脚本，别手动敲 |

实习生最容易被安排的是「排障」——因为老员工都在救火，谁来查那条报错日志？这时候你能不能 10 分钟定位，就是价值。

### 2. "AI + 运维" 是什么

不要被 AIOps 这个词吓到。它从低到高有三个层次：

| 层次 | 做什么 | 难度 | 三周能做到吗 |
|---|---|---|---|
| 用 AI 提效自己 | 让模型帮你读日志、解释报错、写脚本 | 低 | ✅ 第 1 周就能 |
| 把 AI 接进流程 | 告警来了，自动收集上下文，让模型判断根因 | 中 | ✅ 这是你的主线 |
| 做 AIOps 平台 | 异常检测算法、多租户、大规模治理 | 高 | ❌ 不是三周的事 |

你的目标锁在第二层：**做一个「告警 → 自动找证据 → 模型给判断 → 人确认」的闭环**。

为什么选这个？因为它同时用到了运维功底和 AI 工程，是实习生能做出差异化的位置——纯运维你拼不过三年经验的，纯 AI 你拼不过科班的，但「能把 AI 落到运维现场」的人很少。

### 3. 三周后你手上会有什么

不是一个「学习笔记」，而是：

```
一个能跑的系统：一个小服务 + 监控 + 告警 + AI 分析
一份评测数据：recall@5 = 0.8x，20 条测试集，拒答正确率
一段 90 秒演示视频
一页能写进简历的描述（带数字）
```

面试官问「你做过什么」，你放视频；问「效果怎么样」，你给数字；问「怎么做的」，你讲链路。

## 二、五个必须懂的名词

后面每天都会用到，先建立直觉。

### 指标（Metrics）

**是一串随时间变化的数字。**

比如「过去 1 分钟有多少请求」「现在内存用了多少」「请求平均耗时多少毫秒」。

特点：便宜、好存、能画图、能设阈值。缺点：只知道「出事了」，不知道「为什么」。

> 类比：汽车的仪表盘。油表、水温、转速——告诉你车况，但不告诉你发动机哪个螺丝松了。

### 日志（Logs）

**是一条条文字记录，记着「什么时候发生了什么」。**

```
2026-11-10 16:30:01 请求 /slow 耗时 823ms
2026-11-10 16:30:02 数据库连接超时
```

特点：信息量大、能看到细节。缺点：太多、太杂、存储贵。

> 类比：行车记录仪。出事了一帧帧回放，但平时你不会一直盯着看。

### 告警（Alert）

**是「指标超过阈值」时自动发出的通知。**

规则长这样：`如果 P95 延迟 > 500ms 持续 1 分钟，就告警`。

为什么需要它：人不可能 24 小时盯屏幕。告警是机器替你盯。

> 类比：仪表盘上亮起的红灯，加上「嘀嘀」声。

### 容器（Container / Docker）

**是把「程序 + 它需要的一切环境」打包成一个盒子。**

没容器时：这个程序在我电脑能跑，到服务器就报错（因为 Python 版本不一样、少个库）。有容器：盒子在哪都能跑，因为环境一起打包了。

Docker 是最常用的容器工具。你会用它来跑 Prometheus、Grafana 这些现成软件——**不用自己装、不用配依赖，一条命令起来**。

### 大模型（LLM）与 RAG

**LLM**：能读写文字的模型。你给它一段话，它给你一段话。

**它的两个硬伤**：
1. 上下文有限——塞不进 100 篇文档
2. 会瞎编——不知道的东西也敢说得像真的

**RAG（检索增强生成）** 就是治这两个病的：

```
先在你的资料库里搜出最相关的几段 → 把这几段塞给模型 → 让它基于这几段回答
```

这样它就有据可依，不知道就说不知道。

> 类比：开卷考试。不 RAG 是闭卷，靠记忆容易编；RAG 是先翻书找到那一页，再答题。

**Embedding（向量）** 是 RAG 的地基：把一段文字变成一串数字（比如 768 个小数），意思相近的文字，数字也相近。这样「怎么排查延迟高」和「接口变慢怎么办」能被匹配上，哪怕字面完全不同。

## 三、工具速查表

每个工具一句话，后面用到时会再展开。

| 工具 | 是什么 | 为什么用它 |
|---|---|---|
| **Python** | 编程语言 | 运维脚本 + AI 应用都用它，生态最全 |
| **FastAPI** | Python 的 Web 框架 | 20 行就能起一个 HTTP 服务，自带文档 |
| **uvicorn** | 跑 FastAPI 的服务器 | 把 Python 代码变成一个真能访问的端口 |
| **prometheus-client** | Python 库 | 让你的服务能吐出 `/metrics` 数字 |
| **Docker** | 容器工具 | 一条命令跑起 Prometheus / Grafana |
| **Prometheus** | 监控系统 | 定时来「抓」你服务的数字，存起来 |
| **Grafana** | 画图工具 | 把 Prometheus 里的数字画成曲线 |
| **Alertmanager** | 告警路由器 | 决定告警发给谁、怎么发 |
| **jq** | 命令行 JSON 工具 | 快速从日志里挑字段 |
| **stress-ng** | 压力测试工具 | 人为把 CPU 打满，制造故障 |
| **tc** | 网络控制工具 | 人为制造网络延迟 |
| **Chroma** | 向量数据库 | 存 embedding，按相似度检索 |
| **DeepSeek API** | 大模型接口 | 便宜、国内直连、兼容 OpenAI 格式 |

## 四、每天怎么用这份手册

每一天都是一个独立文件，结构完全一样：

```
### 今天的目标         —— 一句话
### 为什么做这一步     —— 不搞懂这个，你只是在抄命令
### 用到的工具         —— 是什么、为什么是它
### 具体步骤           —— 命令 + 每行在干嘛
### 你会看到什么       —— 正常输出长什么样
### 卡住了看这里       —— 最常见的 3 个错误
### 做完检查           —— 打勾，别骗自己
```

**建议的节奏**：

1. 先花 5 分钟读「为什么」和「工具」，不要跳
2. 照着「步骤」敲，**命令一行一行复制，但每行都读一遍注释**
3. 跑不通就看「卡住了看这里」，80% 的问题在里面
4. 最后做「做完检查」，全勾上才算过

**最重要的原则**：看不懂就先照着敲，跑通了再回头理解。**先有体感，再有概念**——反过来会很痛苦。

## 五、卡住了怎么办

按这个顺序：

1. **看报错原文**。不要只看最后一行，往上翻，第一行 `Error` 才是根因
2. **看手册的「卡住了」**。我尽量把常见坑都写进去了
3. **自己先试 10 分钟**。搜报错关键字，或者想想「这一步在干嘛，哪一环断了」
4. **再问我**。把**完整报错**贴过来，别只说「跑不起来」

一个提醒：你现在是在虚拟机上折腾，**搞坏了重装只要 15 分钟**。所以大胆试，别怕。
