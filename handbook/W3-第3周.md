## D15 · 上下文收集器

> **📍 在哪做**：虚拟机 `~/aiops` ｜ 新建 `collector.py` ｜ 需要 Prometheus（9090）在跑 ｜ 终端 1 个

### 今天的目标

写一个函数：给它一个告警，它返回一份「证据包」——指标 + 日志 + 相关文档。

### 为什么做这一步

**这是整个项目里最体现「运维功底」的一步。**

很多人做 AI 运维助手，做法是「把告警文本丢给模型，问它为什么」。这没用——模型只看到一句「P95 延迟高」，它只能瞎猜。

真正有用的做法是：**先把排障时要看的东西自动收集齐**，再让模型基于这些证据推理。

这就像医生看病：不是问「我难受」，而是先量体温、验血、拍片，再下诊断。

**这一步用到的全是你第 1 周学的**：Prometheus 查询、日志筛选、jq 式过滤。

### 用到的工具

| 工具 | 用途 |
|---|---|
| **Prometheus HTTP API** | 用代码查历史指标，比在界面上点更灵活 |
| **requests** | Python 发 HTTP 请求 |
| **第 2 周的 `rag_service.ask`** | 检索相关 runbook |

```python
# collector.py —— 收到告警后，自动收集排障需要的三类证据
import json
import os
import time
from datetime import datetime, timedelta

import requests

PROM = "http://localhost:9090"
APP_LOG = "/home/shawny/aiops/app.log"
WINDOW_MIN = 10          # 看告警前后 10 分钟


# ── 证据 1：指标 ─────────────────────────────────────────
QUERIES = {
    "QPS": 'sum(rate(app_requests_total[1m]))',
    "P95延迟(秒)": 'histogram_quantile(0.95, sum(rate(app_latency_seconds_bucket[1m])) by (le))',
    "5xx错误率": 'sum(rate(app_requests_total{status=~"5.."}[1m])) / sum(rate(app_requests_total[1m]))',
    "服务存活": 'up{job="aiops-app"}',
}


def query_metric(expr: str, minutes: int = WINDOW_MIN):
    """查过去 N 分钟的曲线，返回 [时间, 值] 列表"""
    end = time.time()
    start = end - minutes * 60
    r = requests.get(f"{PROM}/api/v1/query_range", params={
        "query": expr, "start": start, "end": end, "step": "30s",
    }, timeout=10)
    data = r.json()
    if data.get("status") != "success":
        return []
    result = data["data"]["result"]
    if not result:
        return []
    return result[0]["values"]          # [[时间戳, "值"], ...]


def summarize_series(values):
    """把一条曲线压成几个数字，别把 40 个点全塞给模型"""
    if not values:
        return {"状态": "无数据"}
    nums = [float(v) for _, v in values]
    return {
        "最小": round(min(nums), 4),
        "最大": round(max(nums), 4),
        "平均": round(sum(nums) / len(nums), 4),
        "最新": round(nums[-1], 4),
    }


def collect_metrics() -> dict:
    out = {}
    for name, expr in QUERIES.items():
        try:
            out[name] = summarize_series(query_metric(expr))
        except Exception as e:
            out[name] = {"状态": f"查询失败: {e}"}
    return out


# ── 证据 2：日志 ─────────────────────────────────────────
def collect_logs(minutes: int = WINDOW_MIN) -> dict:
    """取时间窗内的错误日志和慢请求，做聚合而不是全量返回"""
    if not os.path.exists(APP_LOG):
        return {"状态": "日志文件不存在"}

    cutoff = datetime.now() - timedelta(minutes=minutes)
    errors, slow, total = [], [], 0

    with open(APP_LOG, encoding="utf-8") as f:
        # 只读最后 5000 行，避免大文件拖死
        lines = f.readlines()[-5000:]

    for line in lines:
        try:
            rec = json.loads(line)
        except json.JSONDecodeError:
            continue
        ts = rec.get("ts", "")
        if ts and ts < cutoff.strftime("%Y-%m-%dT%H:%M:%S"):
            continue
        total += 1
        if rec.get("status", 0) >= 500:
            errors.append(rec)
        if rec.get("latency_ms", 0) > 500:
            slow.append(rec)

    return {
        "窗口内日志条数": total,
        "5xx条数": len(errors),
        "慢请求条数(>500ms)": len(slow),
        "5xx样例": errors[-3:],          # 只给 3 条样例，别塞爆上下文
        "慢请求样例": slow[-3:],
    }


# ── 证据 3：文档 ─────────────────────────────────────────
def collect_docs(alert_name: str) -> list:
    """用告警名去知识库里搜相关的排查步骤"""
    try:
        from rag_service import ask
        r = ask(f"{alert_name} 告警的排查步骤是什么")
        return [{"摘要": r["answer"][:400], "来源": r["citations"]}]
    except Exception as e:
        return [{"状态": f"检索失败: {e}"}]


# ── 汇总 ─────────────────────────────────────────────────
def collect(alert: dict) -> dict:
    name = alert.get("name") or alert.get("alertname") or "UnknownAlert"
    started = datetime.now()
    bundle = {
        "告警": {
            "名称": name,
            "级别": alert.get("severity", "unknown"),
            "摘要": alert.get("summary", ""),
            "触发时间": alert.get("time", started.isoformat(timespec="seconds")),
        },
        "指标": collect_metrics(),
        "日志": collect_logs(),
        "相关文档": collect_docs(name),
        "收集耗时秒": round((datetime.now() - started).total_seconds(), 2),
    }
    return bundle


if __name__ == "__main__":
    demo = {"name": "HighLatency", "severity": "warning", "summary": "P95 延迟超过 500ms"}
    print(json.dumps(collect(demo), ensure_ascii=False, indent=2))
```

## D16 · 让模型做根因分析

> **📍 在哪做**：虚拟机 `~/aiops` ｜ 新建 `analyzer.py` ｜ 复用 `.env` 里的 key ｜ 终端 1 个

### 今天的目标

把证据包喂给模型，让它输出 3 条根因假设、建议动作、以及每条的依据。

### 为什么做这一步

这是「AI」真正上场的地方。但注意——**它不是替你做决定，是帮你缩小范围**。

一个好的输出长这样：

```
假设1（可能性 0.7）：/slow 接口的随机 sleep 导致 P95 升高
  依据：P95 从 0.02s 涨到 0.87s，慢请求日志全部来自 /slow，5xx 为 0
  
假设2（可能性 0.2）：下游依赖变慢
  依据：QPS 未变化，CPU 正常，排除自身负载
  
假设3（可能性 0.1）：网络延迟
  依据：日志中未见连接超时，可能性较低
```

**「依据」这一栏最重要**——它让结论可验证，也防止模型瞎编。

### 用到的工具

| 工具 | 用途 |
|---|---|
| **第 2 周的 `rag.py` 里的 client** | 复用同一个 API 通道 |
| **JSON 输出 + pydantic 校验** | 保证格式稳定 |

### 具体步骤

```python
# analyzer.py —— 把证据包交给模型，输出结构化的根因假设
import json
import os

from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel, ValidationError

from collector import collect

load_dotenv()
client = OpenAI(api_key=os.environ["API_KEY"], base_url=os.environ["BASE_URL"])
CHAT_MODEL = os.environ.get("CHAT_MODEL")

SYSTEM = """你是资深 SRE。根据给定的告警和证据，做根因分析。

必须遵守：
1. 只依据给出的证据推理，证据不足就降低 confidence，禁止凭常识编造
2. hypotheses 必须按可能性从高到低排序，最多 3 条
3. 每条 hypothesis 的 evidence 字段必须引用具体的指标名或日志字段
4. actions 必须是只读的排查命令（如 df -h、ss -tlnp），不要给重启/删除这类危险操作
5. 输出纯 JSON，不要 markdown 代码块

格式：
{
  "summary": "一句话结论",
  "hypotheses": [
    {"cause": "可能原因", "likelihood": 0.7, "evidence": "支持它的具体证据"}
  ],
  "actions": ["只读排查命令1", "只读排查命令2"],
  "confidence": 0.6
}"""


class Hypothesis(BaseModel):
    cause: str
    likelihood: float
    evidence: str


class Analysis(BaseModel):
    summary: str
    hypotheses: list[Hypothesis]
    actions: list[str]
    confidence: float


def analyze(bundle: dict) -> dict:
    payload = json.dumps(bundle, ensure_ascii=False)
    resp = client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM},
            {"role": "user", "content": f"【证据包】\n{payload}\n\n请分析根因。"},
        ],
        response_format={"type": "json_object"},
        temperature=0.2,
    )
    raw = resp.choices[0].message.content
    try:
        data = Analysis(**json.loads(raw))
        return {"ok": True, **data.model_dump(), "raw": raw}
    except (json.JSONDecodeError, ValidationError) as e:
        return {"ok": False, "error": str(e), "raw": raw}


def fmt(result: dict) -> str:
    """把结果排成人能读的样子"""
    if not result.get("ok"):
        return f"分析失败：{result.get('error')}\n原始输出：{result.get('raw', '')[:300]}"

    lines = [f"\n结论：{result['summary']}   (置信度 {result['confidence']:.2f})\n"]
    for i, h in enumerate(result["hypotheses"], 1):
        lines.append(f"假设{i}（可能性 {h['likelihood']:.2f}）：{h['cause']}")
        lines.append(f"    依据：{h['evidence']}")
    if result["actions"]:
        lines.append("\n建议排查动作：")
        for a in result["actions"]:
            lines.append(f"    $ {a}")
    return "\n".join(lines)


if __name__ == "__main__":
    alert = {"name": "HighLatency", "severity": "warning", "summary": "P95 延迟超过 500ms"}
    bundle = collect(alert)
    print(fmt(analyze(bundle)))
```

| 现象 | 原因 | 解决 |

### 为什么做这一步

而且 CLI 的 `--dry-run` / `--confirm` 设计本身就是考点——**AI 运维的核心风险是「模型建议的操作把系统搞坏」**。

```python
# ops_helper.py —— 运维助手的命令行入口
import argparse
import json
import sys

from collector import collect
from analyzer import analyze, fmt

DANGEROUS = ("rm ", "reboot", "shutdown", "kill", "systemctl restart", "drop ", "truncate")


def is_safe(cmd: str) -> bool:
    low = cmd.lower()
    return not any(d in low for d in DANGEROUS)


def cmd_analyze(args):
    alert = {"name": args.alert, "severity": args.severity, "summary": args.summary}
    print(f"[1/3] 收集上下文...")
    bundle = collect(alert)
    print(f"      完成，耗时 {bundle['收集耗时秒']}s")

    print(f"[2/3] 模型分析...")
    result = analyze(bundle)
    print(fmt(result))

    if args.save:
        with open(args.save, "w", encoding="utf-8") as f:
            json.dump({"alert": alert, "bundle": bundle, "analysis": result},
                      f, ensure_ascii=False, indent=2)
        print(f"\n已保存到 {args.save}")

    print("\n[3/3] 建议动作安全审查")
    for a in result.get("actions", []):
        if is_safe(a):
            print(f"  ✅ {a}")
        else:
            print(f"  ⛔ {a}   (危险操作，已拦截)")

    return 0 if result.get("ok") else 1


def cmd_exec(args):
    """执行建议动作 —— 默认只打印，必须显式 --confirm"""
    alert = {"name": args.alert, "severity": "manual", "summary": ""}
    bundle = collect(alert)
    result = analyze(bundle)

    for a in result.get("actions", []):
        if not is_safe(a):
            print(f"⛔ 拒绝执行（危险）：{a}")
            continue
        if not args.confirm:
            print(f"[dry-run] 将执行：{a}")
        else:
            print(f"[执行] {a}")
            import subprocess
            r = subprocess.run(a, shell=True, capture_output=True, text=True, timeout=30)
            print(r.stdout[:1000] or r.stderr[:1000])
    if not args.confirm:
        print("\n以上均未真实执行。确认无误后加 --confirm")


def main():
    p = argparse.ArgumentParser(prog="ops-helper", description="AI 运维助手")
    sub = p.add_subparsers(dest="cmd", required=True)

    a = sub.add_parser("analyze", help="分析告警根因")
    a.add_argument("--alert", required=True, help="告警名，如 HighLatency")
    a.add_argument("--severity", default="warning")
    a.add_argument("--summary", default="")
    a.add_argument("--save", help="把完整结果存成 JSON")
    a.set_defaults(func=cmd_analyze)

    e = sub.add_parser("exec", help="执行建议的排查动作（默认 dry-run）")
    e.add_argument("--alert", required=True)
    e.add_argument("--confirm", action="store_true", help="确认真实执行")
    e.set_defaults(func=cmd_exec)

    args = p.parse_args()
    sys.exit(args.func(args))


if __name__ == "__main__":
    main()
```

## D18 · 故障实验 ×10

> **📍 在哪做**：虚拟机 `~/aiops` ｜ 新建 `faults.sh`、`experiment.md` ｜ **需要 2–3 个终端**：① receiver ② 造故障 ③ 观察

### 今天的目标

造 10 次故障，每次记录「有助手 / 没助手」的定位耗时。

### 为什么做这一步

**这是你简历上唯一的核心数字。** 没有它，前面 17 天都只是「我做了个东西」；有它，你就是「我做了个东西，并且证明它让人快了三倍」。

### 怎么测才可信

关键是**统一计时口径**：

```
起点：告警在 receiver 上出现的时刻（alerts.log 里有时间戳）
终点：你在纸上写下「根因是 XXX」的时刻
```

中间不许偷看 Grafana 之外的提示，也不许提前知道答案。

**两种模式交替做，每次记录**：

| 模式 | 做法 |
|---|---|
| **无助手** | 只看 Grafana + 日志，自己查，记录耗时 |
| **有助手** | 跑 `python ops_helper.py analyze`，验证它给的假设，记录耗时 |

**为什么要交替**：如果你先做 10 次「无助手」再做 10 次「有助手」，你会因为熟练而变快，数字就不准了。交替能抵消学习效应。

### 具体步骤

**1. 准备故障脚本**

```bash
vim faults.sh
```

```bash
#!/usr/bin/env bash
# faults.sh —— 随机触发一种故障，用于实验
set -u
case "${1:-}" in
  cpu)    stress-ng --cpu 2 --timeout 60s ;;
  delay)  sudo tc qdisc add dev ens33 root netem delay 200ms
          sleep 60
          sudo tc qdisc del dev ens33 root ;;
  error)  for i in $(seq 1 30); do curl -s localhost:8000/error > /dev/null; done ;;
  slow)   for i in $(seq 1 100); do curl -s localhost:8000/slow > /dev/null; done ;;
  down)   sudo systemctl stop aiops-app; sleep 30
          sudo systemctl start aiops-app ;;   # 别用 pkill：Restart=always 3 秒就把进程拉起来，故障造不成
  *)      echo "用法: bash faults.sh {cpu|delay|error|slow|down}" ;;
esac
```

> 网卡名用 `ip -o link show` 确认。这台机器是 **`ens33`**（不是 `ens160`）。
> 另外记住 D5 的结论：`localhost` 和本机 IP 都走 `lo`，加在 `ens33` 上测本机服务看不到延迟。

**2. 准备记录表**


```markdown
| 1 | slow | 无助手 | | | | — |
```

**3. 开始跑**

流程（每次）：


### 三个必答题

**Q1：你的 RAG 召回不准时怎么调？**

> 我先看是「检索不到」还是「检索到了但答错」。
> 检索不到的话，第一是改切分粒度，我试过 800 字和 500 字，500 字 recall 高了 0.12；第二是加混合检索，纯向量对专有名词很差，加了 BM25 之后又高 0.09；第三是补语料，缺什么主题补什么，这个最有效但最慢。
> 如果是检索到了但答错，那是 prompt 的问题，我在 system 里强制它只能依据资料回答，并且要求 citations 必须来自资料里的文件名。

**Q2：模型给错建议导致误操作，你怎么防？**

> 四层。第一层是 prompt 里只允许它给只读命令；第二层是代码里有关键词黑名单，`rm` `reboot` 这类直接丢；第三层是默认 dry-run，要 `--confirm` 才真执行；第四层是执行超时和输出截断，防止命令挂死。
> 但我知道这还不够——真正的生产系统要做 RBAC、审批流、审计日志、爆炸半径控制，我这个只是最小演示。

**Q3：你怎么证明这套东西值得做？**

> 10 次注入实验，同一批故障，有助手和无助手交替做，避免学习效应。起点统一是告警出现，终点是写下根因。平均从 11.8 分钟降到 3.2 分钟。
> 不过我也要说明：这个实验规模很小，而且故障是我自己造的，真实环境的复杂度高得多。这个数字只能说明方向对，不能当成生产环境的承诺。
