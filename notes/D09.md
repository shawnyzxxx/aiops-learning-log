## 二、今天踩的坑

### 1. `ModuleNotFoundError: No module named 'pysqlite3'`（rag.py 第 8 行）

**现象**：`python rag.py 磁盘写满了怎么办` 第一行就崩，报的是 pysqlite3 找不到。看起来像"补丁写错了"，其实补丁是对的。

**根因**：**venv 没激活**。对照实测：

| 解释器 | `import pysqlite3` |
|---|---|
| `/usr/bin/python`（系统 3.9.21，未激活时 `python` 就是它） | ❌ ModuleNotFoundError |
| `.venv/bin/python`（激活后 `which python` 指向它） | ✅ OK |

包全装在 `.venv` 里（chromadb 1.5.9 / openai 2.48.0 / pydantic 2.13.5 / pysqlite3-binary 0.5.4.post2），系统 python 看不见。**激活状态不跨终端保留**，每开一个新终端都要重新 `source`。

**解决 + 自检习惯**：

```bash
source .venv/bin/activate
which python     # 必须是 /home/shawny/aiops/.venv/bin/python，看到 /usr/bin/python 就是没激活
python rag.py 磁盘写满了怎么办
```

### 2. `pip install pydantic` 装漏到系统用户目录（隐患，今天顺手挖出来）

历史里那次 `pip install pydantic` 也没激活 venv，结果装到了
`/home/shawny/.local/lib/python3.9/site-packages/`（用户级），而不是 venv 里。

今天侥幸没出事，因为 venv 里 chromadb 本身就依赖 pydantic，已经带了一份 2.13.5。
但 `~/.local` 会**串进系统 python**，以后会出现「明明 pip 装了，venv 里却是另一个版本」这种诡异问题。

> **规矩：先 `source .venv/bin/activate`，再 `pip install`。**

## 三、重要发现（直接影响 D10/D11）

15 条"有答案"的题里，**5 条模型答"资料中没有相关信息"（conf 0.2、citations 空）**：

| # | 问题 | 为什么拒答 |
|---|---|---|
| 3 | Pod CrashLoopBackOff 第一步查什么 | 语料里**完全没有 K8s** 内容 |
| 4 | 数据库连接池耗尽的典型现象 | 没有数据库运维语料 |
| 8 | 证书到期前多久告警、续期流程 | 没有证书/TLS 语料 |
| 13 | 慢查询怎么定位到具体 SQL | 没有 DB 慢查询语料 |
| 14 | 容器被 OOMKilled 后去哪看原因 | 没有容器排障语料 |

**这不是 bug，是语料覆盖缺口**。但它在评测里会被算成"有答案却没召回"，直接把 recall@5 压到最多 10/15 = **0.67**，达不到 0.8 的验收线。

所以 D10 必须二选一（或都做）：

1. **改题**：把这 5 条换成语料真覆盖的主题（告警链路、trace_id、tc 延迟、systemd 端口占用、SRE 概念…）
2. **补语料**：真去写 5 篇 K8s / DB / 证书 / OOM 的笔记进 `corpus/`，再 `python build_index.py` 重建

另外第 5 题（发布回滚）引用的是 `1_目录.md` —— 那文件基本是本书目录，命中它说明检索在"勉强凑答案"，D12 调优时值得单独看一眼。
